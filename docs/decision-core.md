# Optional bounded decision provider

The `decision-core` extra installs the private package from the exact approved
revision `e3040f2e6ee35c8e11cd3c6e8a9d7c7b513bb0ca`. The base arc-cua installation
and existing policies do not import it. Installing the extra requires access to
that repository; it does not publish either package or download model artifacts.

```sh
uv sync --locked --extra dev --extra decision-core
```

The host configures and qualifies a provider, then binds each operation's context.
Endpoint, credentials, deadline, permission and accounting belong to that host.
The task and model cannot choose them.

```python
from arc_cua.policies.decision_core import DecisionCorePolicy, DecisionProviderFailure

factory = DecisionCorePolicy(approved_provider)
operation_policy = factory.bind(operation_context)  # decision_core.CallContext
try:
    decision = operation_policy.decide(subtask=task, snapshot=snapshot, history=history)
except DecisionProviderFailure as error:
    record_failure(error.code, error.receipt)
    # The host owns its explicit handoff/error outcome. No action was produced.
else:
    # Existing host freshness, authorization, materialization and execution gates.
    consume_proposal(decision)
```

`bind` creates a new ChoicePolicy and frozen transport for the operation. Do not
share that bound policy across operations. Each provider call receives the same
operation context directly; there is no mutable current-context global. A host
may share a thread-safe provider and its durable operation allowance. Sharing an
allowance is an explicit host choice, never a bridge default.

The bridge translates every builder-emitted choice without flattening structured
instructions, changing IDs or reordering choices. Existing ChoicePolicy constructs
questions, retains evidence, packs the desktop projection, interprets Jev
confidence and margin, validates completion and proposes actions. Provider profile
byte budgets feed that packer. The final shared codec validates all question kinds,
counts and choice limits before provider IO. Operations, shortcuts, inputs and
targets that exceed a cap fail explicitly. The profile does not silently drop
choices or fabricate a singleton alternative. `min_choices=1` is only a declared
capability; deployed singleton support needs its own qualification evidence.
The existing application `max_candidates` policy remains the builder's own cap.

# Migration differences

The bounded path uses `invalid_retries=0`. Its conformant provider makes one
accounted transport attempt and never falls back. The legacy TypeSafeTransport
continues making up to three HTTP attempts on 429/503/529; that mechanism is
separate from ChoicePolicy's legacy invalid-response retry. Neither legacy behavior
is silently changed.

The shared codec rejects an invalid unused speculative head and returns no partial
batch. Legacy ChoicePolicy validates only the heads consumed by its selected
operation. The bridge requires the shared model label, usage and answer kind and
rejects per-answer extensions. Committed fixtures contain the original consumer
mock and the explicit synthetic format adaptation separately. They do not repair
real provider responses. The codec's probability checks are stricter than the
legacy decoder. A focused regression accepts a 0.99 probability sum on the legacy
path and rejects it on the bounded path, without renormalization.

Typed provider failures become `DecisionProviderFailure` with a bounded safe code.
An InvocationError's receipt is retained for host accounting, including unknown or
received delivery. No provider body, credentials, context binding token or error
text is exposed. Success retains model/usage and request/profile fingerprints in
Decision.raw. No new execution or completion authority is introduced.

# Evidence

Consumer base: `8acf83ff21ce3c8901f94b5f78b175d36b24afa9`.
Shared provider package: `e3040f2e6ee35c8e11cd3c6e8a9d7c7b513bb0ca`.
The copied fixture `tests/fixtures/decision-core-consumer-cases.json` is the exact
issue #2 artifact from that package revision, generated by its real pinned
ChoicePolicy builder. Response fixtures are synthetic. No inference or native
mutation is part of the bridge tests.

`tests/test_decision_core_bridge.py` replays all seven original fixture cases
through both actual policy paths. Six compare exact request bytes, proposed action,
terminal, confidence, margin and packing diagnostics. The overflow case refuses
before either transport. Focused cases cover partial completion refusal,
whole-batch rejection, zero invalid retries, every choice-family cap, question and
capability bounds, singleton refusal, concurrent bound contexts, safe failures and
one reservation/attempt with the real shared HTTP provider and a synthetic IO
seam. The legacy HTTP retry comparison asserts its existing three attempts.

Run the bridge and application regressions with the pinned optional dependency:

```sh
uv run --locked --extra dev --extra decision-core pytest tests/test_decision_core_bridge.py \
  tests/test_choice_policy.py tests/test_typesafe_policy.py \
  tests/test_provider_packing.py tests/test_bounded_decisions.py
```

A private historical replay in the existing packing suite remains unavailable and
skipped; it is neither copied nor used by this migration. Model qualification,
provider spend, private payloads, native application acceptance and deployment are
separate work. This repository has no CI workflow at the inspected base.
